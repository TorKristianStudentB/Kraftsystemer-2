Objektstruktur

  grid
   ├── .Name                 -> str,  navnet på nettet ("Grid")
   ├── .Base                 -> BaseValues-objekt
   │      ├── .Sbase         -> float, S_base [MVA]
   │      └── .Vbase         -> float, V_base [kV]
   │
   ├── .bus                  -> liste med bus-objekter
   │      └── [busindeks]
   │           ├── .busNumber     -> int,   bus-id / bussnummeret
   │           ├── .Name     -> str,   trafostasjon-navn (OBS: stor N = navnet)
   │           ├── .Volt     -> float, spenning [p.u.]
   │           ├── .Angle    -> float, vinkel [rad]
   │           ├── .P_gen    -> float, [p.u.]  (MakeGrid deler MW på Sbase)
   │           ├── .Q_gen    -> float, [p.u.]
   │           ├── .P_load   -> float, [p.u.]
   │           ├── .Q_load   -> float, [p.u.]
   │           ├── .bidz     -> str,   budområde (f.eks. "NO1")
   │           ├── .Vbase    -> float, spenningsnivå [kV]
   │           ├── .V_max    -> float eller None (None hvis kolonnen "Vmax" mangler i excel)
   │           ├── .V_min    -> float eller None
   │           ├── .eic_code -> str eller None (None hvis kolonnen "eic code" mangler)
   │           ├── .kodens_identifikasjonssystem -> int, 0-basert indeks (= plassen i grid.bus,
   │           │                                     brukes som rad/kolonne i Y-matrisen)
   │           ├── .cords    -> [lat, lon] eller None
   │           └── .place    -> [x, y] eller None
   │
   ├── .line                 -> liste med line-objekter
   │      └── [lineindeks]
   │           ├── .lineNumber   -> int
   │           ├── .Name         -> str, "bussfra – busstil"
   │           ├── .R            -> float, [p.u.]  (excel står i ohm, MakeGrid deler på Zbase)
   │           ├── .X            -> float, [p.u.]
   │           ├── .B            -> float, shunt-suseptans (leses urørt fra excel)
   │           ├── .Frombus      -> int, bus-id (busNumber), IKKE indeks
   │           ├── .Tobus        -> int, bus-id (busNumber), IKKE indeks
   │           ├── .lenght       -> float, lengde [m]
   │           ├── .eic_code     -> str eller None
   │           └── .admittans()  -> complex, 1/(R+jX)
   │
   ├── .trafo                -> liste med trafo-objekter
   │      └── [trafoindeks]
   │           ├── .Name         -> str
   │           ├── .Type         -> str  ("tap")
   │           ├── .ratio        -> float, FYSISK spenningsforhold = lav Vbase / høy Vbase
   │           │                    (f.eks. 132/380 = 0.347). Tappen i pu er ratio delt på dette
   │           │                    forholdet, se avsnitt 12.
   │           ├── .Frombus      -> int, bus-id (busNumber)
   │           ├── .Tobus        -> int, bus-id (busNumber)
   │           ├── .R            -> float, [p.u.]  (står allerede i pu i excel, ingen omregning)
   │           ├── .X            -> float, [p.u.]
   │           ├── .eic_code     -> str eller None
   │           └── .admittans()  -> complex, 1/(R+jX)
   │
   ├── .gen                  -> liste med gen-objekter
   │      └── [genindeks]
   │           ├── .name         -> str,   generatornavn
   │           ├── .bus          -> float, bus-id (busNumber) generatoren står på
   │           ├── .P_max        -> int,   Pmax [MW]
   │           ├── .Q_max        -> float eller None, Qmax [p.u.]  (brukes av NR, se avsnitt 11)
   │           ├── .Q_min        -> float eller None, Qmin [p.u.]
   │           └── .eic_code     -> str eller None
   │           (flere generatorer kan stå på samme buss; NR summerer Q_max/Q_min per buss)
   │
   ├── .solution                  -> None til nettet er løst, ellers Solution-objekt
   │      ├── .volt               -> array, spenninger [p.u.] (en per buss)
   │      ├── .angle              -> array, vinkler [rad]     (en per buss)
   │      ├── .iterasjoner        -> int,   antall iterasjoner (NR: Newton-steg)
   │      ├── .mismatch           -> siste feilvektor (se avsnitt 10)
   │      ├── .konvergerte        -> bool,  True hvis løsningen konvergerte
   │      ├── .flow_in_line       -> array, effektflyt per linje (NR/FD: kompleks [p.u.], fra-enden;
   │      │                          DC: reell [MW])
   │      ├── .pv_to_pq_generators-> liste med generatornavn som ble klemt (PV -> PQ), kun NR
   │      ├── .power              -> array, netto P-injeksjon per buss [p.u.] (inkl. slack)
   │      ├── .qower              -> array, netto Q-injeksjon per buss [p.u.] (DC: nuller)
   │      └── .type               -> str, "NR", "DC", "FD", "PP_NR" eller "PP_DC"
   │
   ├── .thevenin(bus1, bus2)      -> Thevenin-impedans mellom to busser (se avsnitt 13)
   ├── .admittansmatrise()        -> Y-buss-matrise (cutsem), complex (N x N)
   ├── .loadflowsolutionNR()      -> lastflyt, Newton-Raphson (med Q-grenser)
   ├── .DCPF()                    -> lastflyt, DC (kun aktiv effekt og vinkler)
   ├── .FDLF()                    -> lastflyt, fast decoupled
   ├── .validating_PP_NR()        -> kjører samme nett i pandapower (AC), lagrer i grid.solution
   ├── .validating_PP_FDPF()      -> kjører samme nett i pandapower (FDPF), lagrer i grid.solution
   └── .validating_PP_DC()        -> kjører samme nett i pandapower (DC), lagrer i grid.solution

------------------------------------------------------------------------------
 11) Q-GRENSER OG PV -> PQ (klemming) I NR
------------------------------------------------------------------------------
# Bussklasser i NR:  "ref" (bus 0) | "PV" (har generator) | "PQ" (ingen generator)
#                    "alene" (ingen forbindelse, hoppes over)
#                    "PQQ" (PV-buss som er klemt på Q-grensen; regnes som PQ i Jacobi)

# Regler:
#  - Hver iterasjon sjekkes hver PV-buss: bussens samlede generator-Q  (= netto Q-injeksjon + Q_load)
#    sammenlignes mot SUMMEN av Q_max og Q_min for generatorene på bussen.
#  - Brytes grensen, klemmes bussen (PQQ): Q settes til grensen, spenningen blir en ukjent.
#    Én buss klemmes om gangen, og alt regnes på nytt med den nye inndelingen.
#  - Når NR har konvergert, sjekkes de klemte bussene: klemt ved Qmax slippes tilbake til PV hvis
#    spenningen er OVER startspenningen (settpunktet); klemt ved Qmin hvis den er UNDER.
#    (en buss kan ha blitt klemt for tidlig mens NR var langt fra løsningen)
#  - Generatorer uten Q_max/Q_min (None) gir ingen grense for bussen.

# Se hva som ble klemt:
grid.solution.pv_to_pq_generators
len(grid.solution.pv_to_pq_generators)

# Kontroller Q for generatorbusser etter løsning [MVAr] (generatorens Q = netto Q + Q_load):
for i, b in enumerate(grid.bus):
    q_gen = (grid.solution.qower[i] + b.Q_load) * grid.Base.Sbase
    print(b.busNumber, round(q_gen, 2))

 12) TRAFOER I Y-MATRISEN (tapp i pu)
------------------------------------------------------------------------------
# trafo.ratio i excel er det FYSISKE spenningsforholdet (lav Vbase / høy Vbase, f.eks. 132/380 = 0.347).
# Bussene er allerede normalisert mot egen Vbase, så en NOMINELL trafo har tapp 1.0 i pu.
# cutsem (admittansmatrise.py) og DCPF regner derfor:
#       ratio_pu = ratio / (lavVbase / høyVbase)         # nominell trafo gir 1.0
#       a = 1 / ratio_pu
# Uten denne normaliseringen blir trafoen feil modellert, og spenningene havner på ca. 0.6 - 1.3 pu.

# Sjekk tappen i pu for alle trafoer:
for t in grid.trafo:
    vf = next(b.Vbase for b in grid.bus if b.busNumber == t.Frombus)
    vt = next(b.Vbase for b in grid.bus if b.busNumber == t.Tobus)
    print(t.Name, t.ratio / (min(vf, vt) / max(vf, vt)))

# Y-matrisen:
Y = grid.admittansmatrise()
Y.shape                     # (N, N), N = antall busser
Y[0, 1]                     # element mellom bussindeks 0 og 1
